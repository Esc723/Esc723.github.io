Privacy policy

Last updated: 12 November 2026 (Asia/Tokyo)

This policy describes how Spreadsheet Sync for GitLab (the "add-on") handles information. The add-on is provided by an individual developer. You can contact the developer at datarateam@gmail.com.

What the add-on is

The add-on runs in Google Apps Script, inside your Google account. The developer does not operate a separate application server. When the add-on needs data from GitLab, Google's Apps Script service sends a request from Google to the GitLab host you configure.

Information the add-on uses

1. GitLab connection settings

When you click Connect, the add-on stores:

  • the GitLab base URL you entered (for example https://gitlab.com, or the URL of your own GitLab instance)
  • your personal access token, if you provided one
  • the GitLab username returned for that token, or the label (public data only, no token) if you did not provide a token

This information is stored in Apps Script user properties. Only the signed-in Google user can read those properties. The token is not written into the spreadsheet, so other editors of the sheet cannot see it.

If you leave the token blank, the add-on still stores the GitLab URL and the public-only label. No token is stored in that case.

2. Sync settings and run status

For each spreadsheet, the add-on stores your sync configuration (project or group path, dataset, filters, schedule, and the target sheet) and the result of the last run (success, error, or a partial fetch). This is also stored in your user properties, not in a server operated by the developer.

A plan value (free or pro) may also be stored in your user properties. Today this defaults to free. A Stripe subscription check is planned and is not built yet. If payment is added later, this policy will be updated before that feature is offered.

3. Data written into your spreadsheet

The add-on writes GitLab records into a sheet in your Google spreadsheet: issues, merge requests, or time logs, including the columns described in the help page. Anyone who can view or edit that spreadsheet can see that data.

If a sync cannot finish in one run, the add-on stores the records fetched so far in a hidden sheet in the same spreadsheet, named _gl2s_checkpoint_ followed by the sync id. That hidden sheet holds JSON for the fetched records. It does not hold your GitLab token. Anyone who can edit the spreadsheet can unhide that sheet. The hidden sheet is deleted when the fetch finishes, or when you remove the sync.

4. Requests to GitLab

The add-on sends requests only to the GitLab host you enter. The default is https://gitlab.com. If you enter another https:// URL, requests go to that host instead.

  • Issues and merge requests are read from that host's REST v4 API (/api/v4/...).
  • Time logs are read from that host's GraphQL API (/api/graphql).
  • If a token is stored, it is sent to that host as an Authorization: Bearer header. The token is not sent to any other host.

The add-on does not send your GitLab token, spreadsheet contents, or Google account data to any other third-party service. Stripe is planned for paid plans and is not used today.

5. Google services that host the add-on

The add-on uses Google Apps Script, Google Sheets, Apps Script user properties, Apps Script triggers, and (when you authorize it) Google's OAuth permission system. Google provides those services under Google's own terms and privacy policy.

The add-on's Apps Script project is configured to log exceptions to Google Cloud Logging (Stackdriver) for that project. An exception log may include an error message and a stack trace. The developer can use those logs only to diagnose failures. You should not put secrets into sheet cells that might appear in an error message, and the add-on does not intentionally log your GitLab token.

6. Google permissions (OAuth scopes)

The add-on asks Google for these permissions:

  • See, edit, create, and delete your Google Sheets spreadsheets (https://www.googleapis.com/auth/spreadsheets). Needed to create sheets, write and update rows, and (for scheduled refresh) to open a spreadsheet by ID when it is not open in your browser.
  • Connect to an external service (https://www.googleapis.com/auth/script.external_request). Needed so Apps Script can call the GitLab host you configure.
  • Show a sidebar and an Extensions menu (https://www.googleapis.com/auth/script.container.ui). Needed so the add-on can present its own menu items and sidebar. Google's consent screen will show its own wording for this scope.
  • Create and manage script triggers (https://www.googleapis.com/auth/script.scriptapp). Needed to create and remove the hourly trigger used for scheduled refresh. Google's consent screen will show its own wording for this scope.

The add-on does not request access to your Gmail, your full Google Drive, or your Google contacts.

What the developer does not do

The developer does not sell your information, does not use it for advertising, and does not use it to build unrelated profiles. The developer does not operate a separate database of your GitLab data or tokens.

Your choices

  • Disconnect in the sidebar clears the stored GitLab URL, token, and username from your user properties.
  • Remove on a sync card removes that sync's configuration and its hidden progress sheet. The visible data sheet is left in place so you do not lose the data already written.
  • You can delete sheets, delete the spreadsheet, or uninstall the add-on from Google in the usual way.
  • You can revoke the add-on's Google authorization from your Google account's third-party access settings.
  • You can revoke a GitLab personal access token in your GitLab account.

Children

The add-on is not directed at children.
