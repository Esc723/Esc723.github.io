Spreadsheet Sync for GitLab

Spreadsheet Sync for GitLab is an unofficial Google Sheets editor add-on. It copies issues, merge requests, and (on the planned paid plan) time logs from GitLab into a spreadsheet.

1. Install and open

When the add-on is listed on the Google Workspace Marketplace, install it from the listing while you are signed in to the Google account you want to use. After you install it, open a Google spreadsheet (a new one is fine).

The first time you install it, a sidebar should open on the right. Later, open it from the Extensions menu:

  1. Extensions
  2. Spreadsheet Sync for GitLab (the menu uses the Marketplace app name)
  3. Open

You can also choose Sync all now from that menu to run every sync saved in this spreadsheet.

The first time you use it, Google asks you to authorize the add-on. That permission dialog is from Google, not from GitLab. You only need to approve it once for your account.

2. Connect GitLab

In the sidebar, under Connect GitLab:

  1. Enter the GitLab URL. The default is https://gitlab.com. You can use your own GitLab instance instead. The URL must start with https://. Do not include a trailing /api/v4 path; the add-on adds the API path itself.
  2. Optionally paste a personal access token that has the read_api scope. Leave the token empty if you only want to sync public projects.
  3. Click Connect.

If the token is present, the add-on checks it by reading the GitLab user it belongs to. If the token is empty, the add-on makes a simple public request to confirm that the server answers, and the sidebar shows you as (public data only, no token).

The token is stored in your own Apps Script user properties. It is not written into the spreadsheet, so other people who can edit the sheet cannot see it. Disconnecting clears the stored connection and token from your user properties.

How to create a token (when you need one)

On GitLab.com or your GitLab instance, create a personal access token with the read_api scope. You do not need a write scope. The add-on only reads GitLab data and writes it into the spreadsheet. It does not create, edit, or close issues on GitLab.

A token is required to read private projects or groups, and it is the reliable way to search the projects and groups you belong to. Time logs are also likely to need a token. Public issues and merge requests on a public project can be synced with the token left blank.

3. Add a sync

After you are connected, use Add a sync:

  1. From: Project or Group.
  2. Data: Issues, Merge requests, or Time logs (Pro).
  3. Project or group path: the full path, for example my-group/my-project or my-group. You can type the path, or click Search and pick from the results.
  4. For issues and merge requests: - State: All, Open, Closed, or Merged (merge requests). - Only with labels: optional, comma-separated. - One column per scoped label: on by default. A GitLab label such as priority::high becomes a priority column whose value is high. If you leave the scope list empty, the add-on creates columns for up to the 10 scopes that appear most often (each must appear on at least 5 percent of the rows). You can type the scopes yourself, for example priority, severity, workflow. - Include description: off by default. Turn it on if you want the issue or merge request description in the sheet. Long text is cut off at Google Sheets' 50,000-character cell limit.
  5. For time logs (Pro): Time logs from the last N days, default 90.
  6. Refresh: Manual only (free), Every hour (Pro), or Every day (Pro).
  7. Click Save. The add-on creates a new sheet named like Issues - my-group/my-project.

The free plan allows one sync in a spreadsheet, issues and merge requests only, and manual refresh. If you choose a Pro option on the free plan, the add-on will refuse to save and will explain why.

Search without a token

The project search asks GitLab for projects you belong to (membership=true). With no token, that search often returns nothing. Group search does not use that membership filter and may still find public groups. In either case you can type the public project or group path yourself, for example gitlab-org/gitlab-runner.

4. Run a sync

On a saved sync card, click Sync now. Or use Extensions > Spreadsheet Sync for GitLab > Sync all now.

While it runs, the sidebar shows "Working...". When it finishes, the card shows a line such as:

Last sync [date and time]: 2585 rows (2585 new, 0 removed)

If GitLab has more items than can be fetched in one run, the add-on stops before the Apps Script time limit, keeps the records it already has, and reports that the sync will continue on the next run. It does not write to the visible sheet until every page has been fetched. Run Sync now again to continue. A half-finished fetch older than six hours is discarded and started again.

A scheduled refresh (Pro) uses a time-driven trigger that runs once an hour. Hourly syncs run on that trigger. Daily syncs run when at least 23 hours have passed since the last successful sync. The trigger is created only when at least one sync in the spreadsheet is set to hourly or daily, and it is removed when none are.

5. How the sheet behaves

  • Synced columns are identified by a note on the header cell, of the form gl2s:id or gl2s:title. You can rename the visible header text and move columns. The next sync still finds them.
  • Columns without that note are yours. The add-on never writes into them. Because rows are updated in place, your values and formulas stay on the same GitLab item. New items are added at the bottom. When an item disappears from GitLab (or no longer matches your filters), that row is deleted and the rows below it move up.
  • Dates such as due dates are written so they do not shift by a day when time zones differ. Date and time values are written as date-times. Time spent and estimates are written in hours, with two decimal places. Text that would otherwise be treated as a formula (for example a title starting with =) is stored as plain text.
  • If you point the add-on at a sheet that already has data and that data was not created by this add-on, it will refuse to write, so it does not overwrite your work. Let the add-on create a new sheet, or start from a blank sheet.
  • If you delete the Issue ID / MR ID / Time log ID column, the add-on can no longer match existing rows and will rewrite the synced columns from the top.

Removing a sync from the sidebar does not delete the sheet. It only removes the sync configuration and any hidden progress sheet used for that sync.

6. Columns

Issues

Issue ID, Reference, IID, Title, State, Type, Author, Assignees, Labels, then any scoped-label columns, then Milestone, Milestone due, Created, Updated, Closed, Due date, Weight, Estimate (h), Time spent (h), Tasks done, Comments, Upvotes, Confidential, URL, and Description if you included it.

Merge requests

MR ID, Reference, IID, Title, State, Draft, Author, Assignees, Reviewers, Labels, then any scoped-label columns, then Milestone, Source branch, Target branch, Created, Updated, Merged, Closed, Time spent (h), Comments, URL, and Description if you included it.

Time logs (Pro)

Time log ID, Spent at, User, Username, Hours, On (Issue or Merge request), Reference, Title, Summary, URL.

Time logs are read with GitLab's GraphQL API. Issues and merge requests are read with GitLab's REST v4 API, 100 items per page, oldest first.

8. Troubleshooting

GitLab rejected the access token. The token may be wrong, revoked, or expired. Create a new personal access token with the read_api scope and connect again.

The token cannot read this resource. The token needs the read_api scope and permission to see that project or group. Private data cannot be read with the token left blank.

Not found. Check the project or group path. Confirm that the project is public, or that the token can see it.

The GitLab URL must start with https://. Change the URL and connect again.

This sheet already has data that was not created by the sync. Use a blank sheet, or let the add-on create a new one.

Another sync is running. Try again in a minute. Wait for the other run to finish, then try again.

Fetched N items so far. The sync continues on the next run. This is expected for large projects. Click Sync now again.

Search returns nothing without a token. Type the public path yourself.

Scheduled refresh does not run. Scheduled refresh is a Pro feature and is not sold yet. On the free plan, use Sync now.

The sidebar opened but the menu is missing, or the editor shows no functions. This can happen right after a new Apps Script project is imported. In the Apps Script editor, add a blank line at the end of Code.gs and Sidebar.html, save, reload the spreadsheet, then run authorization from the Extensions menu. If you are only using the installed add-on from the Marketplace, you should not need to do this.

A hidden sheet named _gl2s_checkpoint_... appeared. That is a temporary progress sheet for a sync that has not finished. It is hidden. Anyone who can edit the spreadsheet can unhide it. It is deleted when the fetch completes, or when you remove that sync. It does not contain your GitLab token.

Could not reach GitLab, or repeated HTTP 500, 502, 503, or 504. The add-on retries with a short delay. If GitLab stays unavailable, try again later.

GitLab kept rejecting requests because of its rate limit. The add-on waits and retries when GitLab returns HTTP 429. If it still stops, wait a few minutes and run the sync again.

9. What the add-on does not do

  • It does not write changes back to GitLab. Editing a cell in the sheet does not update the issue or merge request.
  • It does not use GitLab's OAuth login. You paste a personal access token, or you use public data with no token.
  • It does not send your data to any server operated by the developer. Requests go only to the GitLab host you enter.
